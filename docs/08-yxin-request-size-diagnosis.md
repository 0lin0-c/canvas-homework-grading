# YXIN 10065：请求大小对照与修复

日期：2026-09-24。目标：解释学生 ID `549390` 连续在 Terra 批改阶段失败的原因，并修改可复现的问题。

## 结论及证据边界

对这份固定答卷，故障与发送的图片字节体积有强关联：7,952,745 字节的原请求在缩小请求成功前后均返回 HTTP 403 / 10065；保持原像素尺寸、仅减少 JPEG 编码字节数也能成功。旧代码只对单张大 PNG 转 JPEG，未检查多张图片 base64 编码后的完整 JSON 请求大小。多张大照片累加后，仍会发送重复失败的大请求。

这是可由客户端修复的请求体积兼容问题。YXIN 返回的错误正文只有通用的“网络波动”和错误 ID，没有实际上游异常；实验无法确定其内部是哪一层限制、精确阈值，也不能证明所有 10065 都来自相同原因。没有修改 VPN、代理、模型、提示词或重试次数。

## 真实单次对照

模型、题目、官方答案、学生页面集合、提示词、接口和本机网络配置保持相同。每个诊断请求只发送一次，不自动重试。时间为北京时间。

| 实验 | 开始时间 | 请求字节数 | 四张答卷图尺寸 | 结果 |
| --- | --- | ---: | --- | --- |
| 原请求 A1 | 16:03:49 | 7,952,745 | 每张 3072×4096 | 43.937 秒，403 / 10065 |
| 缩放 B | 16:04:49 | 3,404,417 | 每张 1536×2048 | 29.016 秒，Terra 成功且通过结果校验 |
| 原请求 A2 | 16:05:33 | 7,952,745 | 每张 3072×4096 | 36.766 秒，403 / 10065 |

同像素实验用于区分像素数量和编码体积；正式修复使用长边 2048、quality=88，不使用 quality=50。正式代码构造的 Terra 请求 SHA-256 与成功实验 B 完全一致：`eca9cc843b5c53c2aaa19505a1b794de004c35cc8a862c660ef40e46a0298628`，因此无需再发送相同请求验证。Sol 审查使用 B 的真实批改输出作为初稿。

独立实验记录保存在忽略目录 `prototypes/local/yxin-diagnostics/`，分别为 `original-control-1`、`resized-2048-control-1`、`original-control-2`、`same-pixels-smaller-bytes`、`production-review-verification`。每个目录保存 `diagnostic.json`，成功调用另有 `response.json`。共 5 次单次请求；3 次成功响应记录合计 30,850 token，失败调用的用量未知。诊断没有更新正式批改结果，也没有写回 Canvas。

## 代码修改

`tools/yxin_grader.py` 在构造完整请求后检查 UTF-8 JSON 字节数：

1. 不超过 4 MiB 时保持原请求不变。
2. 超过时处理大图：等比例缩小到长边不超过 2048，用 quality=88 JPEG 编码；未缩放时，仅在 JPEG 更小时替换编码。保留所有图片、文字标签和初稿。
3. 发送前再次检查总字节数；仍超出时明确提示“未发送”，保留模型、阶段和请求指标，不向服务端重复提交。
4. 账本记录每次请求的字节数、SHA-256、所有图像尺寸和图像字节数，便于以后对比类似问题。

4 MiB 是依据本次成功/失败对照选择的保守本机预算，不是供应商官方上限。本地 PNG 不改写，缩放不裁剪、不旋转，归一化证据坐标继续对应原图。已有完整批改结果仍可复用。
