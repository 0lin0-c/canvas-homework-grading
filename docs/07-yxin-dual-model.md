# YXIN 双模型批改与审查

2026-09-24 已对固定答卷的 `10065` 做请求大小对照：原请求 7.95 MB 两次失败，缩小到 3.40 MB 成功；保留原像素尺寸、仅降低 JPEG 字节数至 3.75 MB 也成功。现在先计算完整 JSON 请求字节数，超过本机 4 MiB 保守预算时，才在内存中将大图等比例缩到长边 2048 并用 JPEG quality=88 编码；小于预算的请求保持原样，全部页面和本机证据原图保留。压缩后仍超预算则在发送前拒绝，日志状态为 `not_sent`。`calls[].request` 保存实际请求字节数、SHA-256 和各图尺寸/字节数。4 MiB 是本机经验预算，并非 YXIN 公布的服务端限制；实验与边界见 [请求大小故障排查](08-yxin-request-size-diagnosis.md)。

模型请求失败时，页面显示模型、批改/审查阶段、学生 ID 和运行记录位置。`prototypes/local/yxin-runs/<run-id>/usage.json` 的 `failure` 保存失败位置，`calls[].error.attempts` 保存每次失败的 UTC 时间、HTTP 状态、服务端错误码、响应正文和服务端提供的请求追踪头；重试后成功的失败记录保存在 `calls[].failed_attempts`。正文最多记录 64 KiB，超出时标记 `body_truncated`，当前 API 密钥会脱敏。不记录请求头或答卷请求体；连接失败仍保留用量未知状态。旧运行缺失的信息无法补录。

页面批改按钮调用本机 `tools/serve.py`。后端从忽略的 `.env` 读取 `YXIN_BASE_URL`、`YXIN_API_KEY`，密钥不发给浏览器。默认模型组合：`gpt-5.6-terra` 批改 → `gpt-5.6-sol` 审查。可用 `.env` 的 `YXIN_GRADER_56`、`YXIN_REVIEWER_56` 覆盖模型 ID。

运行前，后端检查模型目录。任一模型不可用，就在**发送学生扫描件之前**拒绝批量任务。2026-09-23 使用当前 YXIN 密钥读取模型目录，确认 `gpt-5.6-terra` 和 `gpt-5.6-sol` 可用。

每名学生先让 Terra 读取九道原题、官方答案和全部学生页面，再让 Sol 读取相同原始材料及初稿。两级模型都返回逐题状态、理由、已读页面和学生证据坐标。服务端校验题号、页面与证据框并裁剪真实扫描件；两级状态不同时将该题列为待核对，不直接扣分。结果用于主页面建议分和编号评语。人工可在页面修改分数与评语，再按“确认并提交”提交当前学生的评分和评语并回读核验，详见 [提交说明](09-canvas-review-submit.md)。模型响应与 token 用量保存在忽略的 `prototypes/local/yxin-runs/<run-id>/`；全部成功后才替换展示结果。

`prototypes/local/batch-source.json` 保存当前作业的题号、原题和官方答案。配置 `CANVAS_API_TOKEN` 后，点击批改会先从 Canvas 自动下载所有已交附件，将 PDF 和图片转为页面，并核对人数、附件、页数和提交版本；任一附件不完整就不会调用模型。当前 9/16 作业已只读验证 30 人、42 个附件、74 页。换成其他作业链接时，仍需先配置对应的题号、原题和官方答案，不会套用旧作业资料。页面已接入逐位人工确认提交和回读核验；旧本地草稿不会自动发送。新作业仍需配置对应原题、答案并核对评分规则。

重复点击时，提交版本及当前原题、答案、模型和批改规则均未变化的学生沿用已有判断；新交或重新提交的学生才分别调用批改和审查模型。若没有变化，本次不调用模型。新一轮完成后旧结果保存在 `prototypes/local/history/`，各次模型响应和 token 账本保存在 `prototypes/local/yxin-runs/`；未变化学生的人工复核草稿继续按其原始复核版本读取。历史 5 人 Codex 对照没有新版提交指纹，因此首次全班 YXIN 批改仍需处理当前全部已交学生。

YXIN 明确返回上游网络波动错误码 10065 时，最多再试两次；其他 HTTP 错误和请求超时不自动重试。已完整批改并审查的学生保存在本次运行的 `partial-result.json`，下次同作业、同答卷版本和同批改配置时可复用；只完成批改、尚未完成审查的学生会重新走两步。大于 1 MiB 的扫描 PNG 仅在发给 YXIN 时转为 JPEG 以缩小请求体，本机证据裁剪继续使用原 PNG。

批改按钮旁的“未提交”入口进入 `unsubmitted.html`。页面实时列出未交学生，可勾选收件人和提醒日期；后端发送前会重新查提交状态，只向仍未提交且未免交的人发送**各自独立**的 Canvas 收件箱消息。结果不等于直接电子邮件送达；是否收到邮件通知取决于学生的 Canvas 通知设置。发送请求及回执状态保存在忽略目录 `prototypes/local/reminder-ledger/`，相同内容不会自动重复发送；响应不明时先人工核对收件箱。

启动：`python tools/serve.py --port 8767`。验证：`python -m unittest discover -s tests -v`。真实模型用量只统计服务端收到的 API usage；Codex 会话工作量不混算。网络超时不会自动重试，防止不明计费状态下重复调用。
