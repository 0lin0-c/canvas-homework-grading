# 人工复核提交 Canvas

在真实作业中，编辑评分及评语后点“确认并提交”。该按钮只处理当前学生，将评分和非空评语写入 Canvas，并独立回读核验。成功后显示“已提交”。空评语只更新成绩，不删除旧评论。修改评语后再次提交会新增评论，不编辑已有评论。

旧版“已确定”仅代表本地确认。升级后保留同一浏览器、同一网址下的评分和评语草稿，但不会自动发送或把旧确认当作已提交。刷新页面后，用户可以核对内容并点击新的提交按钮。

## 实现与核验

- `tools/canvas_review.py`：限定当前真实批改结果、学生 ID 和复核版本；实时核对提交时间、attempt 与全部附件指纹。当前仅支持满分 100 的普通个人计分作业。
- 页面自动调用 `/api/review-state` 读取当前成绩、评论数量及快照，不设置手动读取按钮。提交前服务器再次检查快照；若他人修改过成绩或评论，拒绝覆盖，刷新页面并核对后可再次确认。Canvas API 无跨系统原子比较写入，本机提交锁不能完全消除最后一次检查与写入之间的远程并发窗口。
- `/api/submit-review` 使用 Canvas 单个 submission 的 PUT，设置 `submission[posted_grade]`、`comment[text_comment]`、`comment[attempt]`，评论不群发。不额外调用成绩发布/隐藏接口，实际学生可见性由 Canvas 的评分发布策略决定。
- 回读校验分数和当前作者新增的同文评论，记录评论 ID；只在两者都匹配时返回成功。来源：[Canvas Submissions API](https://developerdocs.instructure.com/services/canvas/resources/submissions)。
- `prototypes/local/review-submissions/<course>-<assignment>-<student>.json` 保存提交账本，写入请求发出前即落盘。重复点击相同内容只回读；连接中断后如果服务端实际已保存，也可通过回读恢复成功。若状态仍不一致，不自动补发评论；先在 Canvas 核对后由维护人员处理该条账本。
- 浏览器继续保存草稿；旧本地确认与真实提交状态分开。服务端提交成功但浏览器状态保存失败时，明确提示“Canvas 已提交成功”，不误报整个提交失败。

## 验证与边界

Python 测试覆盖正常提交、回读、重复点击、发送后断线、未明状态、他人改分/评论、学生重新提交、作业/复核版本错误、成绩范围、示例模式、只改分、局部成功、评论作者校验、PUT 字段，以及本机 HTTP 同源校验。

`node --test tests/test_review_ui.cjs` 用模拟 DOM/API 检查旧草稿保留、真实提交成功状态和失败恢复；不是实际浏览器验收。浏览器控制连接不可用，未替用户点击真实提交。

2026-09-24 对当时作业中一位学生的 submission 做过真实只读核验：满分 100，普通个人计分，答卷指纹匹配，可读取成绩与评论。真实写入权限、实际写入和 Canvas 页面的显示需在用户首次点击“确认并提交”后确认；本次开发没有发送测试评分或测试评论。
